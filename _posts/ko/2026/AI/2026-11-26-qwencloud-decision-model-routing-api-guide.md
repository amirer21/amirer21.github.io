**문의 담당 부서를 고르거나 AI 에이전트로 보낼 작업을 분류할 때는 긴 답변보다 선택 결과가 필요합니다.** QwenCloud의 `decision-model`은 이러한 판단을 전용 API로 처리하는 모델입니다. 일반 챗봇에 “JSON으로 답해 주세요”라고 요청하는 방식과 호출 규약이 다릅니다.

[공식 변경 이력][release]은 **2026년 11월 25일** 모델 공개를 기록합니다. 이 글은 **11월 26일 한국 시간에 확인한 공식 문서**를 바탕으로 용도·가격·제약을 정리합니다. 실제 API를 호출하거나 한국어 정확도를 측정하지는 않았습니다.

## 핵심 요약

- `decision-model`은 분류, 예·아니요 판단, 점수화를 지원합니다.
- [API 문서][api]는 업무 상태와 여러 질문을 한 요청에 담고, 선택 결과·확률 등을 반환하는 구조를 설명합니다.
- 제공 리전은 싱가포르와 중국 베이징으로 안내됩니다.
- 판단 결과를 반환하는 기능과 일반 생성 모델의 JSON Schema 출력 기능은 구분해야 합니다.

## 어떤 문제에 쓰는 모델인가요?

[출시 안내][release]는 문의 분류, 콘텐츠 검토, 에이전트 라우팅, 결과 검증을 활용 사례로 제시합니다.

예를 들어 고객이 “결제는 됐는데 기능을 사용할 수 없습니다”라고 문의하면, 답변 초안을 쓰기 전에 담당 부서와 긴급도를 정해야 할 수 있습니다. 다음 표는 이런 시스템을 설계할 때 사용할 수 있는 예시입니다.

| 판단할 내용 | 애플리케이션에서 쓸 결과 | 후속 처리 |
|---|---|---|
| 결제·기술 중 어느 부서가 적합한가 | 담당 부서 | 담당 큐에 전달 |
| 추가 확인이 필요한가 | 예·아니요 판단 | 운영자 검토 대상으로 분리 |
| 업무 영향이 얼마나 큰가 | 단계별 점수 | 처리 우선순위 결정 |

이 표는 제품의 성능을 측정한 결과가 아니라 **업무 적용을 위한 제안**입니다. 담당 부서를 고르는 작업과 환불 실행처럼 데이터를 변경하는 작업은 별도로 설계하는 편이 좋습니다.

## choice·noul·score는 무엇인가요?

[API 명세][api]는 업무 문맥을 `state`에 넣고, 질문별로 다음 형식을 지정하도록 안내합니다.

| 질문 형식 | 의미 | 반환값을 읽을 때 주의할 점 |
|---|---|---|
| `choice` | 정해진 선택지 중 하나 | 선택과 선택지별 확률을 구분 |
| `noul` | 예·아니요 | 반환 수치는 P(yes)이며 0~1 범위 |
| `score` | 순서가 있는 단계 평가 | 단계 인덱스의 기대값이므로 소수일 수 있음 |

`choice`와 `score`에는 별도의 `confidence`도 반환됩니다. 이를 선택지 확률과 같은 필드로 취급해서는 안 됩니다.

예를 들어 자체 기준을 0~3단계로 만들었다면, 점수 1.6을 곧바로 “위험도 53%”라고 설명할 근거는 없습니다. 우선 각 단계의 의미를 정하고, 실제 사례에서 점수가 어떻게 분포하는지 확인하셔야 합니다.

확률이 높다고 실제 업무에서 늘 맞는다는 뜻도 아닙니다. 자동 처리 여부를 결정할 임계값은 제공사 예제에서 가져오기보다, 우리 데이터의 오분류 비용을 보고 정하는 것이 좋습니다.

## JSON으로 답하는 일반 모델과 무엇이 다른가요?

[QwenCloud 구조화 출력 안내][json]는 일반 생성 모델에서 JSON Object와 JSON Schema 모드를 구분합니다. 전자는 유효한 JSON을, 후자는 지정한 구조를 따르도록 제약하는 기능입니다.

반면 [decision-model API][api]는 `POST /compatible-mode/v1/systemone`으로 호출합니다. 자유로운 답변 문장을 생성하는 대신 정의된 질문에 대한 판단값을 반환한다고 설명합니다.

| 필요한 작업 | 먼저 검토할 방식 |
|---|---|
| 문의에서 담당 부서 하나 선택 | 판단 전용 API |
| 여러 필드를 정해진 스키마로 추출 | 일반 모델의 JSON Schema 출력 |
| 답변 초안·설명문 작성 | 텍스트 생성 모델 |
| 외부 함수를 골라 실행 흐름 연결 | 도구 호출을 지원하는 모델 |

위 표는 요구 사항에 따른 선택 제안입니다. 모델 하나로 모두 해결하려 하기보다 “선택”, “추출”, “설명”, “실행” 중 무엇이 필요한지 먼저 구분하시면 됩니다.

모델의 결과가 JSON 응답에 담긴다는 이유로 일반적인 `response_format` 설정까지 지원한다고 추론해서는 안 됩니다. 공식 [모델 기능표][model]는 Function Calling·웹 검색·일반 Structured Outputs를 미지원으로 표시합니다.

## 가격과 이용 조건

[모델 페이지][model]에 표시된 **2026년 11월 26일 확인 기준 API 정가**는 다음과 같습니다. 월 구독료나 Token Plan 크레딧 환산액이 아닙니다.

| 항목 | 공식 안내 |
|---|---|
| 통화 | 미국 달러, USD |
| 일반 입력 | 100만 토큰당 **$0.042** |
| 출력 | 별도 출력 토큰 단가가 이 페이지에 제시되지 않음 |
| 리전 | 싱가포르·중국 베이징 |
| 할인 | 표는 기간 한정 프로모션을 제외한 정가 |

출력 단가가 없다는 표시를 일반 생성 모델의 “출력 토큰 무료” 요금과 동일하게 해석하지 마십시오. 이 API는 생성 문장 대신 판단 결과를 반환하는 방식입니다.

입력 사용량 합계가 1,000만 토큰이라면, 위 정가에 따른 **입력분 계산은 10 × $0.042 = $0.42**입니다. 실제 청구서나 실행 기록이 아닌 단가 이해를 위한 예시이며, 세금·기타 서비스 비용은 포함하지 않았습니다.

API 명세는 리전에 맞는 엔드포인트와 API 키를 사용하도록 안내합니다. 싱가포르 예제 주소는 `https://ap-southeast-1.maas.qwencloudapi.com/compatible-mode/v1/systemone`입니다. 상세 요청 형식과 환경변수 설정은 [공식 API 문서][api]를 확인하십시오.

한국 전용 리전이나 한국 계정의 가입·결제 가능 여부는 이 글에서 확인하지 않았습니다. 리전 선택과 한국어 판단 품질도 별개의 문제입니다.

## 도입 전에는 무엇을 평가해야 하나요?

먼저 최근 문의 중 정답을 합의할 수 있는 작은 평가 목록을 만드십시오. 모호한 문의, 여러 부서에 걸친 문의, 정보가 부족한 문의를 함께 포함하는 것이 좋습니다.

아래는 특정 모델의 결과가 아닌 검증 절차 제안입니다.

1. 사람이 정한 담당 부서와 판단 근거를 기록합니다.
2. 선택지를 서로 겹치지 않게 정의하고, 분류할 수 없는 경우의 경로를 마련합니다.
3. 모델의 선택·확률·신뢰도를 원본 그대로 저장합니다.
4. 자동 분류와 사람 검토로 넘길 기준을 나누어 평가합니다.
5. 잘못 배정된 문의의 재처리 시간까지 비교합니다.

기존 규칙 기반 분류로 충분한 업무라면 그 방법도 기준선에 넣으십시오. 정확한 키워드로 처리할 수 있는 요청까지 AI로 바꿀 필요는 없습니다. 반대로 표현이 다양해 규칙이 계속 늘어나는 경우에는 모델을 시험해 볼 이유가 있습니다.

가장 중요한 기준은 **전체 정확도 하나보다 잘못된 판단의 영향**입니다. 안내 부서를 잘못 고르는 것과 민감한 작업을 잘못 허용하는 것은 같은 오류 비용이 아닙니다. 처음에는 추천 결과만 기록하는 방식으로 검증하고, 결과가 안정된 작업부터 자동 처리 범위를 정하시는 것이 좋습니다.
