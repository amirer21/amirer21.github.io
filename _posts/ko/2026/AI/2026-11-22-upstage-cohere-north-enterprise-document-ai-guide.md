**사내 문서 AI를 고를 때는 모델 이름보다 문서를 제대로 읽는지, 답변의 근거를 확인할 수 있는지, 직원별 접근 권한을 지키는지를 먼저 보셔야 합니다.** 업스테이지와 Cohere의 최근 협력 발표도 이러한 관점에서 살펴볼 만합니다.

업스테이지는 **2026년 11월 17일** Cohere와의 전략적 협력을 발표했습니다. 이 글은 **11월 22일 한국 시간에 확인한 공식 자료**를 바탕으로 발표 내용과 실무 도입 기준을 정리합니다. 오늘 출시된 신제품 소식은 아닙니다.

## 핵심 요약: 무엇이 발표됐나요?

[업스테이지 공식 발표][news]의 핵심은 다음과 같습니다.

- 업스테이지의 **Solar Pro·Solar Mini**와 문서 처리 기술 **Document Parse**를 Cohere의 기업용 AI 플랫폼 **North**에 통합할 계획입니다.
- 온프레미스와 클라우드 VPC 방식으로 기업·기관에 제공하는 방향을 제시했습니다.
- 한국과 글로벌 기업 시장을 대상으로 공동 사업과 모델 개발 협력을 추진합니다.

이는 새로운 Solar 모델 버전의 출시 공지가 아닙니다. 해당 발표에는 **통합 솔루션의 구체적인 일반 제공일, 공개 가격표, 셀프서비스 신청 절차**가 제시되지 않았습니다. 협력 발표만 보고 기존 North 계정에서 Solar를 곧바로 선택할 수 있다고 판단해서는 안 됩니다.

## 모델 API와 기업용 플랫폼은 무엇이 다른가요?

[Cohere의 North 소개][north]는 조직의 지식과 연결한 에이전트, 업무 자동화, 관리 기능을 설명합니다. 모델을 호출하는 API와 직원이 사용하는 업무 환경은 검토 범위가 다릅니다.

예를 들어 “구매 규정에서 예외 승인 조건을 찾아 주세요”라는 요청을 처리하려면 다음 과정을 나누어 보아야 합니다.

| 단계 | 확인할 문제 | 결과물 |
|---|---|---|
| 문서 읽기 | 스캔·표·제목이 올바르게 해석되는가 | 구조화된 문서 |
| 검색 | 최신 규정의 관련 부분을 찾았는가 | 질문과 관련된 근거 |
| 답변 | 근거를 벗어나 조건을 만들어내지 않는가 | 출처를 확인할 수 있는 설명 |
| 권한 | 질문한 직원이 원문을 볼 수 있는가 | 허용된 자료에 한정된 답변 |
| 운영 | 수정·삭제한 문서가 반영되는가 | 관리 가능한 서비스 |

이 표는 이번 통합 제품의 기능을 보증하는 명세가 아니라, **도입 검증을 위해 제안하는 기준**입니다. 아래 다섯 가지를 데모와 계약 검토에 활용하실 수 있습니다.

## 1. 한국어를 잘 쓰는 것과 문서를 잘 읽는 것을 따로 검사하세요

[Document Parse 입력 문서][input]에는 PDF·HWP·HWPX 등 여러 형식과 한글 OCR 지원이 안내되어 있습니다. [출력 문서][output]는 표·제목·문단 같은 레이아웃을 구분해 HTML로 표현하는 방식을 설명합니다.

따라서 한국어 답변이 자연스럽다는 이유만으로 문서 처리까지 정확하다고 판단하기는 어렵습니다. 실제 업무 자료에서 표의 열과 행, 각주, 페이지 사이에 걸친 조건을 별도로 확인하셔야 합니다.

예를 들어 지급 기준표에서 “월”과 “연”이 뒤바뀌면 문장 자체는 매끄러워도 결론이 틀릴 수 있습니다. 답변 평가 전에 **원문에서 숫자·단위·조건이 올바르게 추출됐는지** 확인하는 편이 원인 분석에 도움이 됩니다.

독립 Document Parse API 문서의 현재 한도도 참고할 수 있습니다.

| 구분 | 파일 크기 한도 | 파일당 페이지 한도 |
|---|---|---|
| 동기 API | 100MB | 100페이지 |
| 비동기 API | 500MB | 2,000페이지 |

이는 11월 22일 확인한 **기존 API의 한도**입니다. North 통합 상품이 같은 형식과 한도를 그대로 제공한다고 확인된 것은 아니므로, 실제 도입 사양은 별도로 문의하셔야 합니다.

## 2. 인용 표시가 아니라 근거의 내용까지 확인하세요

[Cohere의 RAG 인용 문서][citations]는 Command 계열 모델의 Chat API 응답에서 인용된 문장 구간과 출처를 확인하는 구조를 설명합니다. 이 문서를 Solar 통합 버전의 기능 명세로 해석해서는 안 됩니다.

도입 평가에서는 “출처 링크가 있다”에서 한 단계 더 나아가 보십시오.

- 링크를 열면 답변의 숫자와 조건을 실제로 확인할 수 있나요?
- 폐기된 규정 대신 현재 유효한 문서를 인용하나요?
- 근거가 없는 질문에는 확인할 수 없다고 답하나요?

예를 들어 출장비 상한을 물었을 때 과거 규정과 개정 규정이 함께 검색될 수 있습니다. 정답만 채점하기보다 **어떤 문서의 어느 버전을 근거로 삼았는지** 기록하면 재현과 수정이 쉬워집니다.

## 3. 접근 권한은 검색 결과와 답변 양쪽에서 검사하세요

권한 테스트에는 역할이 다른 두 계정을 쓰는 것이 좋습니다. 일반 직원 계정과 인사 담당자 계정으로 같은 질문을 해 보고, 제한 문서의 제목·요약·첨부 파일이 노출되는지 확인하십시오.

“링크를 누르면 접근이 막힌다”는 결과만으로 충분하지 않습니다. 답변이 이미 제한 문서의 내용을 요약해 보여줬을 수도 있기 때문입니다.

이 역시 이번 협력에서 권한 구현이 완료됐다는 주장이 아니라 **실제 도입 때 확인할 항목**입니다. 데모용 관리자 계정 하나로만 시연하면 이러한 차이를 놓치기 쉽습니다.

## 4. 온프레미스·VPC라는 이름보다 데이터 경로를 확인하세요

[Cohere의 비공개 배포 안내][deploy]는 고객이 관리하는 VPC와 온프레미스 배포 방식을 설명합니다. 이번 협력 발표도 이 두 방식을 제공 방향으로 언급합니다.

일반적으로 온프레미스는 조직이 운영하는 인프라에 설치하는 방식이고, VPC는 클라우드 안에서 네트워크를 구분해 구성하는 방식입니다. 배포 위치만 결정했다고 운영 질문이 모두 해결되지는 않습니다.

도입 상담에서는 다음 자료를 요청하는 것이 좋습니다.

- 문서 원본·추출 결과·검색 색인·대화 로그가 저장되는 위치
- 외부로 나가는 호출과 유지보수용 접근 경로
- 보관 기간, 삭제 절차, 백업에서 제거되는 시점
- 모델 업데이트와 장애 복구를 담당하는 주체

“소버린 AI”라는 표현을 검토할 때도 같은 기준을 적용할 수 있습니다. 우리 조직이 통제할 수 있는 데이터와 운영 범위가 어디까지인지 구체적인 구성도로 확인하십시오.

## 5. 토큰 단가보다 업무 한 건의 전체 비용을 비교하세요

이번 통합 상품의 공개 요금이 확인되지 않아 임의의 월 비용이나 절감률은 제시하지 않습니다. 독립 API 가격을 그대로 통합 솔루션 가격으로 쓰는 것도 적절하지 않습니다.

견적은 다음 항목을 나누어 요청하시면 비교하기 쉽습니다.

| 비용 항목 | 견적에서 확인할 내용 |
|---|---|
| 초기 구축 | 설치·문서 이관·시스템 연결 범위 |
| 문서 처리 | 신규 문서와 수정 문서의 재처리 기준 |
| 추론·인프라 | 모델 실행 자원과 사용량 과금 방식 |
| 운영 | 저장·백업·모니터링·업데이트·지원 |
| 검수 | 사람이 오류를 수정하고 재확인하는 시간 |

실용적인 지표는 **“직원이 검수해 사용할 수 있는 답변 한 건당 비용”**입니다. 호출 단가가 낮아도 근거를 다시 찾는 시간이 길면 업무상 이득이 줄어들 수 있습니다. 이는 특정 제품의 측정 결과가 아니라 비교를 위한 제안입니다.

## 지금 검토할 팀과 먼저 준비할 일

한국어 문서가 많고, 데이터 처리 환경을 직접 통제해야 하는 기업의 개발·플랫폼 담당자라면 이번 협력의 구체적인 제공 조건을 문의해 볼 만합니다. 반면 개인 문서 몇 개를 요약하려는 이용자에게 기업용 플랫폼 구축이 우선이라고 보기는 어렵습니다.

통합 제품의 제공 일정이 확정되기 전에도 평가 자료는 준비할 수 있습니다. 아래 수량은 공식 기준이 아닌 **작은 개념 검증을 위한 예시**입니다.

1. 공개 자료나 사용 승인을 받은 비식별 문서 10개를 고릅니다.
2. 표·각주·개정 이력·스캔 품질이 다른 자료를 섞습니다.
3. 정답을 알고 있는 질문 20개와 근거 문서 위치를 적습니다.
4. 답할 수 없는 질문과 권한상 답하면 안 되는 질문도 포함합니다.
5. 정답·근거·권한·처리 시간·사람의 수정 시간을 같은 표에 기록합니다.

제공사에는 통합 버전의 제공일, 지원 모델과 문서 형식, 배포 리전, 계정·계약 조건, 평가 환경을 문의하십시오. 이 글에서는 실제 통합 환경의 접속·설치·성능 시험을 수행하지 않았습니다.
