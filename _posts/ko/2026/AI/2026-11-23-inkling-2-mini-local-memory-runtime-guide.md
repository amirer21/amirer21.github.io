**Inkling 2 Mini는 로컬에서 실행할 수 있도록 가중치가 공개된 멀티모달 모델입니다. 다만 ‘약 20GB’라는 모델 크기만 보고 20GB 메모리에서 충분히 작동한다고 판단하면 안 됩니다.** 내 컴퓨터에서 사용할 수 있는지는 하드웨어, 실행 도구, 입력 길이를 함께 확인하셔야 합니다.

Thinking Machines Lab은 [2026년 11월 20일 Inkling 2 Mini를 공개][launch]했습니다. 이 글은 **11월 23일 한국 시간에 확인한 공식 자료**를 기준으로, 새 구조의 의미와 실제 선택 기준을 정리합니다. 직접 설치하거나 처리 속도를 측정한 체험기는 아닙니다.

## 핵심 요약

- 텍스트·이미지를 입력받아 텍스트를 출력하는 모델입니다.
- [공식 모델 카드][card]는 Apache 2.0 라이선스와 공개 가중치, Tinker를 통한 이용 경로를 안내합니다.
- 내부의 같은 층을 반복 사용하는 구조가 특징입니다. 작은 저장 크기와 계산량은 구분해야 합니다.
- 로컬 실행은 가능하지만 모든 노트북이나 모든 버전의 실행 도구에서 같은 조건으로 동작하는 것은 아닙니다.

## 같은 층을 세 번 쓰는 구조는 무엇인가요?

[모델 카드][card]에 따르면 저장된 층은 24개이고, 가운데 12개 층을 세 번 통과합니다. 가중치를 공유해 반복하는 방식입니다.

통과 횟수를 계산하면 **앞 6개 + 가운데 12개 × 3회 + 뒤 6개 = 48회**입니다. 저장된 층이 48개로 늘어나는 것은 아닙니다.

비유하면 새로운 작업 공간을 계속 추가하기보다, 같은 작업 공간을 다시 사용해 계산을 이어가는 방식입니다. 다만 반복할 때도 연산은 발생하므로 “모델 파일이 작다”와 “토큰 하나를 생성하는 계산이 적다”는 같은 뜻이 아닙니다.

숫자를 비교할 때도 주의하셔야 합니다. 공식 수치는 전체 **26.4B**, 활성 파라미터 **3.4B**, 반복 통과를 반영한 토큰당 유효 활성 규모 **5.4B**를 구분합니다. 여기서 B는 10억 단위입니다. 마지막 숫자를 모델 전체 저장 크기로 읽으면 안 됩니다.

## 약 20GB 모델인데 왜 32GB 이상을 안내하나요?

[모델 카드][card]는 배포 체크포인트를 약 20GB로 설명하며 다음 실행 환경을 안내합니다.

| 환경 | 공식 안내 |
|---|---|
| Apple silicon | 메모리 32GB 이상 장치 |
| NVIDIA DGX Spark | 지원 실행 환경 |
| 그 밖의 GPU·플랫폼 | 가능성이 있으며 VRAM 32GB 이상 권장 |

일반 RAM, GPU의 VRAM, Apple silicon의 통합 메모리는 같은 자원으로 취급할 수 없습니다. Windows PC의 시스템 RAM이 32GB라고 해서 GPU VRAM 32GB 조건을 충족하는 것은 아닙니다.

또한 모델 가중치 외에도 실행 도구와 대화 문맥을 유지하는 메모리가 필요합니다. 모델이 올라간다는 사실만 확인하지 말고, **실제로 쓸 입력 길이에서 여유가 있는지** 검사하는 편이 좋습니다.

이 차이는 긴 문서를 다룰 때 더 중요해집니다. 모델 카드의 최대 문맥 길이는 1M 토큰이지만, [vLLM 공식 실행 안내][vllm]는 하드웨어별 설정을 구분하고 H100·DGX Spark 설정에서 메모리에 맞추기 위해 문맥을 262,144토큰으로 제한한다고 설명합니다. **모델의 최대 지원 길이가 내 장치의 실행 가능 길이를 보장하지는 않습니다.**

## 어디서 시작할 수 있나요?

| 목적 | 먼저 확인할 경로 | 확인할 조건 |
|---|---|---|
| 모델을 내려받기 전 대화 확인 | Tinker Playground | 계정·이용 조건 |
| Apple silicon에서 로컬 실행 | Ollama 모델 페이지 | 메모리와 실행 도구 지원 |
| NVIDIA에서 API 서버 구성 | vLLM 실행 레시피 | GPU·지원 버전·문맥 설정 |
| 가중치와 모델 정보 확인 | 공식 Hugging Face 저장소 | 파일 형식·라이선스·제약 |

[Ollama 공식 모델 페이지][ollama]에는 다음 실행 명령이 안내되어 있습니다. Ollama를 설치하고 모델을 지원하는 환경을 준비한 뒤 사용하는 명령이며, 이 글에서 직접 실행한 결과는 아닙니다.

```bash
ollama run inkling-2-mini
```

첫 다운로드에는 네트워크와 저장 공간이 필요합니다. 모델을 로컬에 둔다고 연결한 검색 도구나 외부 API까지 오프라인으로 바뀌는 것은 아니므로, 사용할 앱의 호출 경로도 확인하십시오.

서버 운영 목적이라면 일반적인 설치 명령만 복사하기보다 [vLLM 전용 레시피][vllm]를 보시는 것이 좋습니다. 확인 시점의 안내에는 **아직 정식 릴리스되지 않은 0.35.0 이상 지원을 위한 nightly wheel 또는 전용 이미지**가 명시되어 있습니다. 기존 안정 버전에 모델 이름만 넣으면 된다고 가정하지 마십시오.

Tinker에서 이용할 수 있다는 발표를 한국 계정의 결제·접속 보장으로 확대하지 않았습니다. 이 글에서는 한국 계정으로 가입하거나 결제하지 않았으며, API 요금도 확인하지 않아 가격 비교를 싣지 않습니다.

## 코딩용으로 바로 교체해도 될까요?

[출시 발표][launch]는 코딩·도구 사용 평가에서의 강점을 강조하지만, 여러 조건을 지키는 지시나 긴 다중 턴 대화의 한계도 설명합니다. 공급자가 공개한 벤치마크를 모든 개발 업무의 우위로 일반화하기는 어렵습니다.

[공식 Hugging Face 모델 카드][weights]에는 특히 반복적인 추론에 갇히거나, 프로젝트 규칙을 놓치거나, 작업 결과를 부정확하게 보고할 수 있다는 주의가 있습니다. 출력 토큰과 에이전트 차례 수에 한도를 두는 방안도 안내합니다.

처음에는 작은 테스트 수정처럼 결과를 판별할 수 있는 작업을 맡기는 것이 좋습니다. 아래는 특정 제품의 측정 결과가 아니라 **비교 실험을 위한 제안**입니다.

1. 실패하는 테스트 한 개와 기대 동작을 제공합니다.
2. 수정 범위를 한 모듈로 제한합니다.
3. 동일한 요청을 현재 사용하는 모델에도 제공합니다.
4. 테스트 통과 여부와 불필요한 변경을 비교합니다.
5. 응답 시간뿐 아니라 사람이 다시 고치는 시간도 기록합니다.

“완료했다”는 답변보다 실제 diff와 테스트 출력을 확인하십시오. 첫 비교에서 전체 저장소의 자율 수정을 맡기면 모델 성능과 작업 범위 문제를 구분하기 어렵습니다.

한국어 품질도 별도로 검사하셔야 합니다. 일반 다국어 지원이라는 안내를 한국어 지시 이해나 문서 작성 품질의 보증으로 읽을 수는 없습니다.

## 어떤 독자에게 유용한가요?

이미 적절한 장치를 갖추고 로컬 코딩 보조, 이미지 기반 입력, 자체 서비스 연결을 실험하려는 개발자라면 검토할 만한 새 선택지입니다. 저장된 가중치를 재사용하는 구조에 관심 있는 분에게도 살펴볼 가치가 있습니다.

반면 장비 구매가 필요한 경우에는 먼저 원격 이용 경로에서 자신의 작업을 평가하는 편이 합리적입니다. 노트북 실행 시연만 보고 새 장비를 구매하기보다 **작업 품질 → 지원 도구 → 필요한 메모리 → 운영 비용** 순서로 결정하십시오.
